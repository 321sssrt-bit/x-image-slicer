# X 切图：需求调研与技术设计记录

整理日期：2026-11-16。完整工程实施规格见 [SPEC.md](../SPEC.md)。

## 已确认的核心需求

- **形态**：Chrome / Edge 浏览器扩展（Manifest V3）。
- **输入**：支持选择单张本地静态原图，或直接切分当前新建帖子发帖框内已添加的单张静态图片（框内切图）。
- **完成边界**：切图后自动按顺序填入 X 发帖框，全部上传就绪后自动关闭切图窗口并在原发帖框展示状态与顺序核验提示，最终由用户亲自点击发布。
- **切图张数**：每次打开默认切成 `8` 张，支持 `2`～`20` 张整数调节，并提供个人推荐档位（`5` / `8` / `20` 张）快捷切换；不做跨会话自动记忆或根据宽高比强制修改初始数量。
- **大图本地自动优化**：支持最高 5 亿像素（500,000,000 px，含 4 亿像素高解析大图）原图，在本地以每片最终上传切片为单位控制尺寸（长边 `≤ 4096 px`）与文件体积（`≤ 4.5 MB`），保留透明通道，具体工程预算与瀑布流策略以 [SPEC.md](../SPEC.md) 为准。
- **展示目标**：围绕 X 单帖多图横向连续浏览（`1×N` 左右等分）设计，不套用旧四图宫格，也不引入竖长图上下分页。

## 平台背景与多图轮播调研

- X 平台单帖媒体附件上限由 4 个提升至 20 个（详见 [4Gamers 报道](https://www.4gamers.com.tw/news/detail/83283/x-twitter-support-20-image-or-video)）。
- 20 张是单帖附件上限而非强制输出张数；扩展支持 `2`～`20` 张任意调节。
- 针对单图体积限制（5 MB），本项目采用每片 `≤ 4.5 MB`（`4,500,000 B`）作为留有安全余量的工程预算，并设定单片长边 `≤ 4096 px` 初值。
- 实测参考帖的 Syndication 媒体数据显示：20 张横向连续拼接切片在宽度无法被 20 整除时，采用余数均匀分配（各片宽度相差不超过 1 像素，例如 18 张 `819×1287` 与 2 张 `818×1287`，总宽 `16378×1287`）。本项目同样采用累计像素边界算法确保 100% 覆盖原图全宽。

## 开源同类项目对比

在设计阶段检索并对比了 GitHub 上的同类切图与发帖辅助项目：

- [Shirolin/X-Puzzle-Kit](https://github.com/Shirolin/X-Puzzle-Kit)（GPL-3.0）：提供 Chrome 扩展与网页/PWA，支持 `N×1` / `1×N`、四宫格、T 型预览与图片/ZIP 导出，但公开流程止于导出文件，不包含自动填入 X 发帖框及框内切图链路。
- [moruton1119/x-image-splitter](https://github.com/moruton1119/x-image-splitter)（MIT）：本地网页切图工具，支持横向 2/3/4 份、轮播预览、ZIP/单张下载及打开 X 发帖页，不直接向发帖框注入切片。
- [jackwener/OpenCLI](https://github.com/jackwener/OpenCLI)：通用浏览器自动化工具，包含文件输入与 `DataTransfer` 路径参考，但面向命令行自动化发布且限制为 4 张图。
- [munimoni/Twitter_image_splitter](https://github.com/munimoni/Twitter_image_splitter)（MIT）：支持 2/3/4 份切图、分割线调整及本地下载。
- [beephole/splitterTwitter](https://github.com/beephole/splitterTwitter)：Python/Tk 四宫格本地保存工具。

综合对比后，本项目定位为**极简专用扩展**：专注于 `1×N` 左右等分（`2`～`20` 张）、5 亿像素（500MP）大图本地优化、框内单图直接切分替换、自动填入 X 发帖框与顺序校验，并严格保留用户手动发布的最终边界。

## 关键实现边界

- **真实比例预览**：切片预览按实际上传文件的几何比例展示，并标注每片像素尺寸与编码体积；不通过拉伸把窄片伪装成宽卡片。
- **累计坐标等分**：使用累计边界计算每片起止横坐标，确保覆盖原图全宽、不丢尾部像素；大图等比缩小时整组共用同一缩放比例与输出高度。
- **目标发帖框强绑定**：入口与操作严格绑定同一个新建帖子发帖框（区分主页内联发帖框与弹窗发帖框，排除回复框与引用框），保护已有文案；遇到多张已有媒体、视频、动图或投票冲突时明确拦截提示。
- **上传完成判定与无关进度条排除**：X 发帖框工具栏附近常驻字数统计圆环（`role="progressbar"`，`aria-valuemax="280"`）或隐藏/空白状态节点。适配器仅依据与目标媒体上传相关的有效状态判断是否仍在上传，避免无关页面控件导致「8/8 已就绪仍超时」的误判。
- **自动关窗与顺序独立核验**：确认全部切片上传就绪后立即自动关闭切图窗口，将键盘焦点交还原发帖框并在框内保留状态横幅；左到右顺序核验结果（「已填入 N 张切片，等待发布」或「请检查顺序后再发布」或「顺序不一致警告」）独立更新到发帖框横幅中。
- **框内切图安全替换**：当发帖框内仅有 1 张静态图片时，支持直接读取完整原图进行切分预览；仅在全部合格切片生成完毕且用户点击「确认替换并填入发帖框」后才移除原附件并填入切片。若移除原附件后出现部分上传失败，在当前窗口会话内存中保留原图供一键下载，不做持久化存储，也不静默清空现有草稿。
